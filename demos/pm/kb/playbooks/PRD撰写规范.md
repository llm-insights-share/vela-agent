# PRD 撰写规范（星河控股产品部 · Demo）

> 结构对齐业界 PRD 最佳实践（问题导向、SMART 目标、范围 In/Out、用户故事、验收与埋点、风险依赖），参考公开 PRD 模板与「人人都是产品经理」等社区对 BRD/MRD/PRD 分工的共识，改写为星河内部规范摘要。

## 1. 文档分层

| 文档 | 回答的问题 | 读者 |
|------|------------|------|
| BRD | 为什么做、商业价值 | 业务/管理层 |
| MRD | 为谁做、市场与竞品 | 产品/市场 |
| PRD | 怎么做、做到什么算完 | 设计/研发/测试 |

## 2. 完整版 PRD 必备章节

1. 文档信息（作者、版本、状态、变更记录）
2. 概述（2–3 段）
3. 背景与机会
4. **问题陈述**（核心，须引用数据/访谈）
5. 目标用户与场景
6. 目标与成功指标（SMART，含口径）
7. 范围：In / Out
8. 用户故事与主流程
9. 功能需求与异常分支
10. 埋点与数据需求（可链到独立埋点表）
11. 里程碑与依赖
12. 风险与待确认项

## 3. 精简版（MVP / 紧急迭代）

文档信息 → 问题陈述 → 目标与指标 → 核心功能 3–5 个 → 用户故事 2–3 → 里程碑 → 高风险项。

## 4. 质量红线

- 每个关键决策须有证据（指标、访谈、竞品、工单），禁止「我觉得」。
- 指标必须可埋点或可从现有报表取数。
- Out of Scope 必须写，防止范围蔓延。
- 待确认项单独成表，标注负责人。

## 5. 协作节奏（参考）

产品起草 → 设计/研发/数据评审 → 干系人共识 → 锁定版本进入开发。
