# 埋点需求规范（星河控股产品部 · Demo）

> 对齐社区对「埋点 PRD」的共识：分清产品埋点与数据埋点（DRD）、写清事件名/触发时机/页面位置/属性；复杂多端业务应单独维护事件表。参考人人都是产品经理《埋点 PRD 模板》等公开实践。

## 1. 原则

**要看什么数据，埋什么点。** 无消费方的点不埋。

## 2. 事件表必备字段

| 字段 | 说明 |
|------|------|
| event_name | 稳定英文名，snake_case |
| trigger_timing | 精确到交互瞬间，禁止「用户使用时」 |
| page_or_module | 页面/模块 |
| properties | 属性名、类型、枚举 |
| owner_pm | 负责人 |
| status | draft / planned / active / deprecated |

## 3. 正反例

- 反例：`user_click`（过宽，无法分析）
- 正例：`approval_action_click` + `action=approve|reject` + `ticket_type` + `latency_ms`

## 4. 与 PRD 关系

- MVP：PRD 内嵌埋点小节即可
- 多端/复杂：独立 DRD，PRD 只引用事件 ID
- 评审冻结后变更须记版本
